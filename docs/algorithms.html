Concepts

Algorithms

Every number RepoAtlas shows comes from a small set of deterministic, iterative graph algorithms in a pure library with no I/O. Use Prev, Next and Play to step through each one on a tiny example; without JavaScript each illustration shows its final state.

Determinism

Nodes are processed in sorted path order, adjacency lists are sorted and nothing is recursive (real repositories exceed Python's recursion limit). The same commit always yields the same graph, cycles, roles and ranks — which is what makes analyses cacheable per commit.

From source files to a graph

  1. Parse (ast_parser.py) — Python with the standard-library ast (imports inside if TYPE_CHECKING: are marked type-only; a line-based fallback recovers imports from files with syntax errors); JS/JSX/TS/TSX with tree-sitter: import, export … from, import x = require(), and import("…") / require("…") calls whose argument is a string literal (or a template literal without substitutions). Exports, top-level functions and classes are collected too.
  2. Resolve (resolver.py) — relative specifiers, tsconfig/jsconfig baseUrl + paths (nearest config per directory for monorepos, @/ and ~/ fallbacks), extension and index.* probing, ESM .js → .ts rewriting; Python relative/absolute imports against detected source roots. Bare packages are external (counted, not edges); asset imports (.css, .svg, .json, …) are ignored; anything else that points nowhere is unresolved.
  3. Build (graph_algorithms.py) — deduplicate edges per (source, target), drop edges to unknown files, keep self-loops, build sorted forward and reverse adjacency.
  4. Analyze (pipeline.py) — detect cycles, then compute per-file degrees, role and PageRank. One pathological file never aborts the run: it gets a parse warning instead.

An edge A → B always means A imports B.

Blast radius: reverse BFS

To answer “what could break if I change this file?”, RepoAtlas walks the graph backwards — from a file to every file that imports it, then to their importers, and so on — with a breadth-first search over the reverse adjacency. BFS visits files in order of distance, so each impacted file gets its shortest depth (1 = imports the file directly).

With N files in the analysis and depth d(f) for each impacted file f:

impact%  = impacted / (N − 1) × 100
risk     = Σ (1 / d(f)) / (N − 1) × 100        (both rounded to 2 decimals, 0 when N ≤ 1)
level    = LOW if risk < 5 · MEDIUM if < 15 · HIGH if < 35 · otherwise CRITICAL
LOW < 5 5 ≤ MEDIUM < 15 15 ≤ HIGH < 35 CRITICAL ≥ 35

The risk score weights direct dependents fully and distant ones less (½ at depth 2, ⅓ at depth 3…), so a file imported directly by half the repository scores higher than one reached through a long chain. Running the BFS from every file gives the dashboard's “riskiest files”.

Cycle detection: three-colour DFS + Tarjan

Circular imports are found in two passes over the forward graph:

  • An iterative three-colour DFS — white unvisited, grey on the current path, black finished — records a concrete cycle whenever it meets a grey file (a back edge). Each cycle is rotated so its smallest path comes first; at most 100 are reported.
  • Tarjan's strongly connected components then marks every file and import that lies on any cycle (components with more than one file, or a self-import), even when the DFS reported only one of several overlapping cycles. These become is_circular and scc_id.

The DFS keeps an explicit stack of (file, iterator over its imports) plus the current path, so the cycle for a back edge u → v is simply the path from v to u. Tarjan uses the same explicit-stack technique with index/lowlink values; SCC ids are numbered by each component's smallest path.

Role classification

Each file gets exactly one role from its in-degree (number of distinct files importing it) and out-degree (number of distinct files it imports). Self-imports count in neither. Rules are checked top to bottom; the first match wins:

#RoleConditionTypical file
1Isolatedin = 0 and out = 0Stand-alone script, unused module
2Entry pointin = 0 and out > 0main.py, CLI, page, test
3God modulein ≥ 5 and out ≥ 5Heavily used and heavily coupled hub
4Core utilityin ≥ 5 and out ≤ 2Config, helpers, shared types
5Leafout = 0 (and in > 0)Constants, small models
6Standardeverything elseOrdinary module

Centrality: PageRank

PageRank ranks files by how much of the codebase ultimately depends on them. Importance flows along import edges, from importer to imported file: a file imported by important files becomes important. RepoAtlas runs the classic power iteration with damping 0.85 for exactly 50 iterations (deterministic, no convergence test), starting from 1/N everywhere. Files that import nothing (dangling nodes) spread their rank evenly over all files, so the ranks always sum to 1.

rank'(v) = (1 − 0.85) / N
         + 0.85 × Σ rank(dangling) / N
         + 0.85 × Σ over importers u of v:  rank(u) / out_degree(u)

Drift matching: sliding windows

When a tour is synced, each step's pinned snippet is looked for in the new version of its file (drift_detector.py). All comparisons use normalised lines: each line is stripped and runs of whitespace collapse to one space, so re-indentation alone never counts as a change.

  1. Healthy? Hash the same line range in the new file; equal to snippet_hash → Healthy.
  2. Moved? Slide a window of the snippet's length over the whole file; every exact normalised match is a candidate and the one nearest the original start line wins (ties: earliest) → Auto-fixed.
  3. Changed. Otherwise the step Needs review. The best fuzzy window (difflib.SequenceMatcher ratio over the normalised text, window lengths n−2 … n+2) is proposed if its similarity is at least 0.75; otherwise the original range, clamped to the file, is shown for review.

Complexity

For a graph with N files and E unique import edges:

OperationTimeNotes
Build graphO(E log E + N log N)Dedup + sorted adjacency lists
Blast radius (one file)O(N + E)Reverse BFS on the cached graph
Riskiest files (dashboard)O(N · (N + E))One BFS per file
Cycle detectionO(N + E) + O(C · L)DFS + Tarjan; canonicalising C reported cycles of length L (C ≤ 100)
Role classificationO(N + E)Degrees, then O(1) per file
PageRankO(50 · (N + E))Fixed 50 iterations
