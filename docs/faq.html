FAQ & limitations

What RepoAtlas analyzes, what it deliberately ignores, and what happens to the code you point it at.

Limitations

AreaLimit
RepositoriesPublic GitHub repositories only. Private ones are rejected as GITHUB_REPO_NOT_FOUND; RepoAtlas never requests repository access.
LanguagesPython, JavaScript and TypeScript: .py, .js, .jsx, .mjs, .cjs, .ts, .tsx, .mts, .cts. Declaration files (.d.ts…) and minified bundles are skipped.
SizeAt most MAX_FILES source files per analysis (1,500 by default), prioritising src/, app/, lib/ and packages/*/src/, then shallower paths; the analysis is flagged truncated when the cap is hit. Files over 300 kB and archives over 80 MB are not processed. See prioritisation.
Skipped foldersnode_modules, .git, dist, build, .next, out, coverage, __pycache__, .venv, venv, vendor, site-packages, .tox, .mypy_cache.
CyclesThe list of concrete cycles is capped at 100. Circular membership (is_circular on files and imports) is always complete, because it comes from Tarjan's SCC.
What is an edgeOnly imports that resolve to another analyzed file in the same repository. External packages (react, numpy, the standard library) are counted as external imports but are not edges. Asset imports in JS/TS (.css, .svg, .json, images, fonts, .md, .vue, …) are ignored entirely. Imports that should resolve but don't (e.g. an alias missing from tsconfig) are counted as unresolved.
Dynamic importsimport("…") and require("…") are detected only when the argument is a string literal (or a template literal without ${…}). Computed paths, Python importlib.import_module() / __import__() and runtime plugin loading are invisible to static analysis.
SnapshotsEach analysis is pinned to one commit. To see newer code, analyze again (unchanged commits are served from cache) or run Sync & verify on a tour.
Parse warningsA file gets a warning only when the parser had to recover from a syntax error that could affect its imports or exports. tree-sitter-typescript 0.23 rejects some valid TypeScript type syntax (e.g. generic call signatures in object types); errors confined to type-only constructs are therefore ignored, because types cannot contain imports. Files with a warning still contribute every import that could be recovered.
ToursCheckpoints have 2–6 options; steps are completed strictly in order; a step pins one contiguous line range in one file.

Privacy & security

  • Code is parsed, never executed. Files are read as text and turned into syntax trees (Python ast, tree-sitter). Nothing from the repository is imported, built, installed or run.
  • Archives are handled in memory with guards: only regular files are read (no symlinks or hardlinks), absolute and .. paths are rejected, sizes are capped and binary or non-UTF-8 files are skipped.
  • What is stored: repository metadata, the analysis results and the text of the analyzed source files at the pinned commit (so the code viewer, tour pinning and drift checks work without calling GitHub again). Because only public repositories are accepted, this is code that is already public.
  • Identity: sign-in is GitHub OAuth through Supabase Auth with no repository scopes. The API stores the Supabase user id and GitHub username on tours, sync runs and progress. Access tokens are verified per request and never logged.
  • Database access goes only through the API. Supabase exposes tables through its Data API with the browser-visible key, so every table has Row Level Security enabled with no policies — direct access from browsers is denied. The frontend build fails if a Supabase secret key is ever placed in a public (NEXT_PUBLIC_) variable.
  • Secrets in configuration (database URL, GitHub token, Gemini key, JWT secret) are typed as secret values and masked in logs, error reports and debug output.
  • Checkpoint answers (correct_index, explanation) are only ever sent to the tour owner; trainees receive the explanation only after answering correctly.
  • Report vulnerabilities as described in the security policy.

AI is optional

Every core feature — graphs, roles, cycles, PageRank, blast radius, tours, drift detection — is deterministic and works without any AI. A server operator can optionally set GEMINI_API_KEY to enable one extra endpoint, POST /api/v1/ai/step-draft, which drafts a tour step (title, Markdown explanation, optional checkpoint) for a selected line range.

  • The prompt is grounded in facts the engine already computed (role, degrees, direct imports and dependents, blast radius, cycle membership) plus the numbered snippet and up to 10 lines of surrounding code on each side.
  • The model output is re-validated against the same contracts as a hand-written step; invalid checkpoints are dropped. The draft is only a suggestion — nothing is saved until the owner saves the step.
  • Drafts are cached per commit, file, range and content hash; uncached requests are limited to 20 per user per 10 minutes. The API key is sent only in a request header, never in URLs or logs.
  • Without a key, the endpoint answers 503 AI_DISABLED and GET /api/v1/meta reports ai_enabled: false.

Frequently asked questions

Why does a file show no imports even though it clearly imports things?

Its imports are probably external packages (not edges by design) or could not be resolved — for example a path alias that is configured in a bundler but not in tsconfig.json/jsconfig.json, or a file that was cut off by the MAX_FILES cap. The analysis summary shows the external and unresolved counts.

Are risk scores comparable between repositories?

Roughly: impact and risk are normalised by the number of other files (N − 1), so they express “what share of this codebase is affected”. A CRITICAL file in a 20-file project affects far fewer files in absolute terms than one in a 1,000-file project. See the formulas.

Why are my tests and scripts marked as entry points?

Any file that imports something but is imported by nothing is an entry point by definition (role rules). Tests, CLIs, pages and config files usually fit that description.

Does Sync & verify re-analyze the repository every time?

Only if the branch has a new commit. If the latest commit was already analyzed, that analysis is reused and the sync only re-checks the steps.

What happens to a tour step when its file is renamed?

Drift detection looks for the snippet in the same path, so a renamed file shows up as File deleted. Use Re-pin to another file in the builder; title, explanation and checkpoint are kept.

Can I analyze a branch other than the default?

Yes — paste a /tree/<branch> URL or open “Choose a branch”. The branch is resolved to its current commit, and tours created from that analysis sync against the same branch.

Can I take the analysis with me?

Yes — Export report in the graph toolbar downloads an ARCHITECTURE.md with a Mermaid diagram of the central files, the riskiest files, roles and cycles, all linked to the analyzed commit. See Export an architecture report. The raw data is also available from GET /api/v1/analyses/{id}/graph.

Why is the very first request slow?

The public demo API runs on Render's free plan, which sleeps when idle and needs about 50 seconds to wake. The web app sends a silent health request as soon as any page loads, so the API usually finishes booting while you read the landing page.

Can I run my own instance?

Yes. It is MIT-licensed and runs on free tiers — see Self-hosting. On your own instance you can raise MAX_FILES and the size limits.
