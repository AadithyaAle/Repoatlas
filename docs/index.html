RepoAtlas documentation

See how a codebase fits together — with onboarding docs that heal themselves.

RepoAtlas parses a public GitHub repository into an interactive file-dependency graph, simulates the blast radius of changing any file, and lets maintainers author onboarding tours pinned to exact lines of code that are automatically re-verified — and re-located — after every commit.

Why RepoAtlas

Onboarding onto an unfamiliar codebase is slow. Newcomers grep for entry points, guess which modules are load-bearing and read wiki pages that were accurate three refactors ago. Documentation lives next to code instead of on it, so it silently goes stale the moment someone moves a function.

RepoAtlas attacks both halves of the problem:

  • Structure you can see. Imports are extracted from real syntax trees (Python ast, tree-sitter for JavaScript/TypeScript), resolved to files and rendered as an explorable graph, with roles, cycles and centrality computed by deterministic graph algorithms.
  • Docs that can't rot unnoticed. Every tour step stores the exact lines it explains plus a SHA-256 fingerprint. A one-click Sync & verify re-checks every step against the latest commit, auto-fixes steps whose code merely moved and flags the ones that really changed.

OSS maintainers

Publish a guided tour of your architecture and keep it correct as contributors refactor — the sync report tells you exactly which steps need attention.

Team leads

Spot god modules, circular imports and risky files before a change ships; follow trainee progress and first-try checkpoint accuracy on the dashboard.

New developers & students

Start from entry points and the most central files, walk an ordered tour with checkpoints, and see what breaks if you touch something.

The four workflows

Everything in RepoAtlas is one of four end-to-end workflows. Each card links to the detailed state machine.

01

Analyze a repository

Paste a GitHub URL. The commit is pinned, the source archive downloaded in one request, every file parsed and the dependency graph computed by a background worker.

Ingestion state machine → 02

Simulate blast radius & find cycles

Select any file to see every file that imports it directly or transitively, a depth-weighted risk score, and every circular dependency in the repo.

Blast radius flow → 03

Build & take onboarding tours

Owners pin line ranges, write Markdown explanations and add multiple-choice checkpoints. Trainees complete steps strictly in order.

Tour lifecycle → 04

Sync & verify tour health

Re-analyze the branch head, re-locate every pinned snippet with a sliding-window matcher and get a per-step health report with one-click resolutions.

Feature highlights

  • Real parsers, not regexPython via the standard-library ast; JS, JSX, TS and TSX via tree-sitter. Syntax errors never abort an analysis.
  • Import resolution that knows your setuptsconfig/jsconfig paths and baseUrl (including extends and monorepos), @/ aliases, index files, ESM .js→.ts, Python packages and src/ layouts.
  • Blast-radius simulationReverse BFS gives direct and transitive dependents, impact percentage and a depth-weighted risk score with four risk levels.
  • Complete cycle detectionIterative three-colour DFS reports concrete cycles; Tarjan's SCC marks every file and import that lies on any cycle.
  • Roles & centralityEvery file is classified (entry point, god module, core utility, leaf, isolated, standard) and ranked with PageRank.
  • Pinned to a commitEach analysis is tied to one commit SHA, so graphs, file contents and tour anchors are reproducible and cacheable.
  • Self-healing toursMoved code is re-located automatically; changed code gets a proposed location, similarity score and side-by-side diff.
  • Checkpoints that can't be peekedCorrect answers and explanations are never sent to trainees; progress is enforced in tour order on the server.
  • DashboardRiskiest files per repository, role and language breakdowns, tour health scores, sync history and trainee progress.
  • Documented REST APIContract-first OpenAPI 3.1 with a uniform {success, data, error} envelope and stable error codes.
  • Free-tier friendlyA durable job queue embedded in the API process means one free web service plus a free Postgres is enough.
  • Safe by designPublic repositories only; archives extracted in memory with traversal, symlink and size guards; analyzed code is never executed.
