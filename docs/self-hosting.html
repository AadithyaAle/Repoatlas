Self-hosting

RepoAtlas runs on a laptop with Docker, and in production on three free tiers: Supabase (Postgres + Auth), Render (the API, with its worker embedded) and Vercel (the frontend). These docs deploy to GitHub Pages.

Local development

Requirements: Docker, Python 3.12+ with uv, and Node.js with npm (CI uses Node 24).

  1. Start Postgres 16 from the repository root. It listens on localhost:5433 (user/password/database atlas/atlas/repoatlas), so it never clashes with a local Postgres on 5432.

    docker compose up -d db

  2. Run the API on port 8000. The defaults in .env.example already point at the Docker database; the embedded worker starts with the server.

    cd backend
cp .env.example .env
uv sync
uv run alembic upgrade head
uv run uvicorn app.main:app --reload --port 8000

    Interactive API docs: http://localhost:8000/docs.

  3. Run the frontend on port 3000 in a second terminal. Leave the Supabase variables blank to run anonymously — analysis, graphs, blast radius and public tours work; sign-in shows a “not configured” state.

    cd frontend
cp .env.example .env.local
npm ci
npm run dev
Tests and quality gates

CI runs exactly these. Backend integration tests use the separate database repoatlas_test on the same server — create it once, e.g. with docker compose exec db createdb -U atlas repoatlas_test.

# backend/
uv run ruff format --check . && uv run ruff check .
uv run mypy app
uv run pytest
# frontend/
npm run lint && npm run typecheck && npm run test && npm run build
npm run gen:api   # after changing backend schemas: regenerate openapi.json + TS types

To run the worker as its own process, set WORKER_MODE=standalone on the API and start uv run python -m app.workers.analysis_worker. The container image builds with docker build -t repoatlas-api backend and runs migrations before starting uvicorn.

Docs site

Set window.REPOATLAS_APP_URL and window.REPOATLAS_API_URL in docs/assets/config.js once the services exist; they power the “Open the app” buttons and the base URL in the API reference. Empty values are safe.

Deployment

Order matters only for URLs: create Supabase first, then Render and Vercel, then go back and fill in each service's public URL where the others need it.

1 · Supabase

  1. Create a project. Note its reference (https://<ref>.supabase.co).
  2. Database URL. Open Connect and copy the Transaction pooler connection string (port 6543), with your database password filled in (URL-encode special characters). This is the API's DATABASE_URL. The API disables prepared statements so it works through the pooler, and the container applies migrations itself at start-up.
  3. GitHub OAuth app. On GitHub: Settings → Developer settings → OAuth Apps → New OAuth App. Homepage URL: your frontend URL. Authorization callback URL: https://<ref>.supabase.co/auth/v1/callback. Copy the client ID and generate a client secret.
  4. Enable the provider. Supabase → Authentication → Sign In / Providers → GitHub: paste the client ID and secret and enable it.
  5. URL configuration. Authentication → URL Configuration: set Site URL to https://<frontend> and add https://<frontend>/auth/callback to the Redirect URLs (add http://localhost:3000/auth/callback too for local sign-in).
  6. Keys. From the API keys settings copy the project URL and the publishable key (sb_publishable_…) for the frontend. New projects sign tokens with asymmetric keys, verified through JWKS from SUPABASE_URL — no secret needed. Only if the project still uses the legacy HS256 secret, also set SUPABASE_JWT_SECRET on the API.

2 · Render (API)

  1. New → Blueprint, connect the repository. Render reads render.yaml at the repository root: one Docker web service repoatlas-api (free plan, region Singapore, rootDir: backend, health check /api/v1/health, auto-deploy) with ENVIRONMENT=production, WORKER_MODE=embedded, LOG_LEVEL=INFO, MAX_FILES=1500.
  2. Set the secret variables (declared with sync: false, so Render asks for them): DATABASE_URL, CORS_ORIGINS (e.g. ["https://<frontend>"]), SUPABASE_URL, SUPABASE_JWT_SECRET (leave empty unless HS256), GITHUB_TOKEN (recommended) and GEMINI_API_KEY (optional).
  3. Deploy. The container runs alembic upgrade head, then uvicorn on $PORT. Check https://<service>.onrender.com/api/v1/health → {"success": true, "data": {"status": "ok", "database": "ok"}}.
Free plan cold starts

Free Render services sleep when idle; the first request afterwards can take about 50 seconds while the container boots. Queued analyses are safe — they live in Postgres and the embedded worker picks them up as soon as the service is awake again.

3 · Vercel (frontend)

  1. Import the repository and set the Root Directory to frontend (framework: Next.js).
  2. Environment variables: NEXT_PUBLIC_API_URL (the Render URL, no trailing slash), NEXT_PUBLIC_SUPABASE_URL, NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY, NEXT_PUBLIC_SITE_URL (the Vercel URL) and optionally NEXT_PUBLIC_DOCS_URL.
  3. Close the loop: put the final frontend origin into the API's CORS_ORIGINS and into Supabase's Site URL / Redirect URLs, then redeploy the frontend if you changed any NEXT_PUBLIC_* value.

4 · GitHub Pages (docs)

  1. Repository Settings → Pages → Build and deployment → Source: GitHub Actions.
  2. .github/workflows/docs.yml runs on pushes to main that touch docs/**, the READMEs, CONTRIBUTING.md, SECURITY.md or the backend API/schemas (and on demand):
    • links — lychee checks the READMEs and every docs/**/*.html page, including #fragment anchors (also on pull requests);
    • build — regenerates docs/openapi.json from the backend with app.scripts.dump_openapi and uploads docs/ as the Pages artifact;
    • deploy — publishes it to https://aadithyaale.github.io/Repoatlas/;
    • verify-live — waits for the CDN and link-checks the live pages.
  3. The site is plain HTML/CSS/JS with no build step; .nojekyll disables Jekyll processing and 404.html is served for unknown paths.

Troubleshooting

SymptomCause and fix
GitHub rate limit reached (GITHUB_RATE_LIMITED)Anonymous GitHub access allows 60 requests/hour per server IP. Set GITHUB_TOKEN on the API (5,000/hour). GET /api/v1/github/rate-limit shows the remaining quota and reset time.
Repository not found (GITHUB_REPO_NOT_FOUND)The repository is private, renamed or misspelled. Only public repositories can be analyzed.
Repository too large (REPO_TOO_LARGE)The source archive is over MAX_TARBALL_BYTES (80 MB). Raise it on your own instance if memory allows — archives are processed in memory.
No supported source files (NO_SOURCE_FILES)The repository is empty, or has no Python/JS/TS files outside skipped directories (node_modules, dist, build, vendor, …).
Analysis stays PENDINGNo worker is running: check WORKER_MODE (off disables it; standalone needs the separate process) and look for “Embedded analysis worker started” in the API logs. On Render's free plan the service may simply be waking up.
Analysis stuck in a running state after a restartThe job's lock goes stale after WORKER_STALE_LOCK_SECONDS (10 minutes) and it is reclaimed automatically; after 3 attempts it is marked FAILED. Re-submitting the repository resets a failed analysis.
Browser console: CORS errorThe frontend origin is missing from CORS_ORIGINS. It must be a JSON list with the exact origin, e.g. ["https://repoatlas.example.app"] — no path, no trailing slash.
401 “Token signing key not recognized” / “Unsupported token algorithm”SUPABASE_URL points at a different project, or the project uses HS256 and SUPABASE_JWT_SECRET is not set.
503 “Authentication service unavailable”The API could not fetch the JWKS from SUPABASE_URL; check the URL and outbound network access.
Sign-in redirects to localhost or fails at /auth/callbackSupabase Site URL / Redirect URLs don't include https://<frontend>/auth/callback, or the GitHub OAuth app's callback is not https://<ref>.supabase.co/auth/v1/callback. Check NEXT_PUBLIC_SITE_URL.
“Sign-in not configured” in the appNEXT_PUBLIC_SUPABASE_URL or the publishable key was missing at build time. Set them on Vercel and redeploy.
/api/v1/health returns 503The database is unreachable. Verify DATABASE_URL (pooler host, port 6543, password) and that the Supabase project is not paused.
First request takes ~50 sRender free-plan cold start; subsequent requests are fast.
API reference on this site is empty when opened from diskBrowsers block fetch() on file://. Serve the folder: python3 -m http.server 8080 --directory docs.
CI “API schema changed”A backend schema changed without regenerating the client types. Run npm run gen:api in frontend/ and commit openapi.json and src/lib/api/schema.d.ts.
